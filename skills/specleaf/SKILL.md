# SpecLeaf

将现有 OpenAPI 3.0 / 3.1 YAML / JSON 文件或模块目录转换为可离线阅读的 HTML。沿用项目现有契约，生成时保持入口及引用文件只读。

## 选择输入和输出

- 优先使用用户指定路径，其次检查项目已有文档命令和约定，再在相关目录中寻找入口。区分包含 `openapi`、`info`、`paths` 的契约与被引用的模型片段。存在多个无明确关系的候选时，澄清生成范围。
- 单个契约使用文件输入；汇总多个模块使用其公共目录。目录模式递归识别准确命名的 `openapi.yaml`、`openapi.yml`、`openapi.json`，同一目录只能有一个入口。跳过隐藏目录、`node_modules`、`dist`、`build`、`coverage` 及目录符号链接。
- 各模块保留独立版本、服务地址、鉴权和引用作用域；无需手动合并契约或重命名同名模型。
- 输出遵循用户路径或项目约定；没有约定时可用 `./openapi.html`，显式传入 `-o`。已有文件时确认它是本任务要更新的产物，避免覆盖无关文件。

## 调用 CLI

需要 Node.js 22.19.0+。优先复用项目已有文档命令或已安装的 `specleaf`：

```bash
specleaf "./docs/apis" -o "./docs/api.html"
```

输入、输出相对调用目录解析；`$ref` 相对包含它的文件解析。不要切换到 skill 目录执行生成。

若只有项目内安装的 CLI，可通过 `npm exec --offline -- specleaf` 调用。若 CLI 不可用，读取本 skill 同目录安装记录 `specleaf.json` 的 `version`，用该版本执行 `npx --yes specleaf@版本 输入 -o 输出`，替换其中的版本和路径。没有安装记录时，先核实可用版本。获取 npm 包可能需要联网，应遵循当前环境的网络权限；包与依赖齐备后，本地生成无需联网。

## 处理失败

- 缺失引用：根据报错的来源文件和 JSON Pointer 检查相对路径、目标文件和目标字段。
- 重复入口：报告具体目录及候选入口，不擅自删除或重命名契约。
- 无模块入口：检查范围和入口命名，避免将模型目录作为模块集合。
- 远程入口、远程 `$ref`、Swagger 2.0 不受支持；说明限制和所需的本地 OpenAPI 3.0 / 3.1 输入。
- 输出与入口或引用文件冲突时更换输出路径。修复契约内容应属于用户请求的范围，不能为生成成功编造接口、字段或示例。

## 验收与交付

确认命令退出码为零、输出 HTML 存在且非空。需要浏览器验收且环境具备条件时，检查标题、搜索和接口导航；只在实际验证后报告这些结果。

交付 HTML 文件链接、输入范围、使用版本和可复现命令。产物包含脚本、样式和契约，可以单独复制并在浏览器离线打开。页面仅供阅读，不执行接口请求。生成成功表示完成解析与渲染，不代表完整的 OpenAPI / JSON Schema 语义校验。
